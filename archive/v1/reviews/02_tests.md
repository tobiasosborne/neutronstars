# Test Coverage Review — NeutronStars Pipeline

Reviewer scope: `test/runtests.jl` (140 lines, 6 testsets) plus
`verification/` harnesses. Reviewer did **not** run the tests; question is
whether passing tests prove what their authors claim.

---

## Executive summary — top three testing risks

1. **The headline physics claims have zero automated regression coverage.**
   HANDOFF.md states "T profile matches McPHAC within 1.2%", "B=0 limit
   recovers non-magnetic to <0.1%", "F/σT⁴ = 0.99", "Phase 3b smoke test
   converges in ~60 iterations". None of these are asserted in
   `test/runtests.jl`. The only end-to-end test is the magnetic flux smoke
   test with `rtol=0.25` — i.e. a 25% drift would still pass. The
   non-magnetic solver, the TOV solver, the Schwarzschild tracer, the
   colorimetry pipeline, the surface dipole model, and the entire
   `SpectralImageCube` render path have **no `@test` coverage at all**.

2. **Where there are tests, most lock in numerical fingerprints rather
   than physics.** The "Vacuum-polarized mode vectors" testset
   (`test/runtests.jl:38–71`) hard-codes 14 magic numbers to `rtol=1e-8`
   to `1e-10`. These pin the *current code output* down to last-digit
   precision but neither (a) prove the values are physically correct nor
   (b) tolerate an algorithmically equivalent reformulation. They are
   change-detectors, not physics checks. Conversely, the structural tests
   (`> 0`, `< 1`, `== 0.0`, `≥ 80.0`) at `:13–22`, `:73–94`, `:119–143`
   prove only that the code runs, not that any answer is right.

3. **The verification scripts are reproducible but not gated.** The
   Suleimanov Fig. 2 pipeline has a real pass/fail metric harness
   (`verification/check_suleimanov_fig2_metrics.py`) with documented dex
   thresholds — this is the project's best-engineered verification — but
   it is not run by `test/runtests.jl`, has no Julia equivalent, and the
   `eos_checks.jl` / `potekhin_table_comparison.jl` harnesses print
   PASS/FAIL to stdout with no exit code. Project.toml has no `[extras]`
   or `[targets]` section (Test is not even an explicit dep); there is no
   `.github/workflows/` directory; nothing prevents a future agent from
   silently breaking the 1.2% McPHAC agreement.

## Missing edge cases — prioritised

Priority A (would catch a real, plausible regression):

1. **B = 0 limit consistency**. Run `solve_magnetic_atmosphere(T, g, 0.0, 0.0, gaunt)` and `solve_atmosphere(T, g, gaunt)`; assert the two emergent spectra agree to `<0.1%` per HANDOFF claim. This catches any breakage of the `B>0` / `B==0` branching in `magnetic_atmosphere.jl:278-298`, `dielectric_tensor.jl:131-133`, `magnetic_ff.jl:109,172,198`. Today this branch divergence is unmonitored.

2. **θ_B singular angles**. `polarization_weights_cold` (`dielectric_tensor.jl:74-84`) hard-codes return values when `sinθ < 1e-8` or `cosθ < 1e-8`. No test feeds θ_B = 0 or π/2 to either `polarization_weights_*` or `mode_opacity`. The "Magnetic mode opacity separation" testset uses θ=π/4 only.

3. **TOV regression: M_max(BSk21) = 2.27 ± 0.02 M_☉**, **R(1.4 M_☉) = 12.6 ± 0.2 km**, **visible_fraction(u=1/3) = 0.75 exactly**. These three lines would lock in three of the most fundamental physical results in the pipeline.

4. **`solve_atmosphere` non-magnetic flux conservation**. `@test F/(σT⁴) ≈ 1.0 rtol=0.02` at T=1e6, g=2e14. Currently the non-magnetic Rybicki path is entirely untested.

5. **Magnetic flux test tolerance**. `:116` uses `rtol=0.25`. Tighten to `rtol=0.05` (still 5× slacker than the HANDOFF-claimed 0.03) and the test will fail-loud the next time the solver drifts.

Priority B (would catch convergence/numerical hazards):

6. **Non-convergence is a negative outcome**. The solvers return a struct with `converged::Bool`. There is no test that the code *correctly identifies* non-convergence. Suggested negative test: `solve_magnetic_atmosphere(...; max_iter=1)` should return `converged=false`. (Currently nothing prevents a future change from setting `converged = true` unconditionally.) Equivalently, a test that asserts the iteration loop does not silently accept an obviously-bad ΔT (e.g. via the `ΔT .*= 0.3 / max_dT` damping at `magnetic_atmosphere.jl:131-134` swallowing all corrections).

7. **High β_e regime** (β_e ≫ 10). The Coulomb-log machinery (`coulomb_magnetic.jl:44-46`) sums Landau levels with `N_max = max(2, ceil(3/β_e + 2))` capped at 50; at the tested β_e ≈ 16.5 (`test/runtests.jl:24-35`) `N_max = 2`. There is no test at β_e ≈ 100 (B=1e15, T=1e6) where the cap or the sinh overflow guard would matter.

8. **Low β_e regime** (β_e < 0.1). `coulomb_log_magnetic` falls back to classical (`coulomb_magnetic.jl:36-38`). No test verifies the fallback is smooth at β_e = 0.1 ± ε.

9. **Frequency under/overflow**. `nu_ff_alpha` and friends have `u < 500.0 ? (1 - exp(-u)) : 1.0` cutoffs (`magnetic_ff.jl:74`, `:90`, `:157`); none tested. `coulomb_log_classical_safe` has a u/2 > 300 asymptotic branch (`coulomb_magnetic.jl:120-123`); not tested.

10. **Frequency grid bounds**. `make_frequency_grid` runs from `0.05 k_B T / h` to `120 k_B T / h`. No test at the edge frequencies. The Wien tail (ν ≫ k_B T / h) is where opacity tables, exp cutoffs, and Planck function all converge to extreme values; underflow there silently produces zeros that contribute to flux only as `0 × dν`.

Priority C (architectural):

11. **`_log_interp` edge cases** (`feautrier.jl:296-318`). Used by the un-wired adaptive solver. With `y_old` having a single element or with `x_new` outside the range, behaviour is `y_old[end]` clamp without warning.

12. **TOV `denominator > 0` assertion** (`tov.jl:173`). The horizon trap throws `AssertionError`. No negative test that pathologically high ρ_c does the right thing.

13. **`solve_tov` with `ρ_c < 1e10` or `> 1e16`** throws assertion. No test.

14. **CIE colorimetry round-trip** at T=5778 K → (255, 252, 245). Documented in `VERIFICATION_LOG.md:49-54`; not asserted.

15. **`rt_emergent_spectrum` interpolation edge cases** (`rt_atmosphere.jl:191-242`). Behaviour at `ν < ν_grid[1]` uses Rayleigh-Jeans `(ν/ν_min)^2`, at `ν > ν_grid[end]` returns `0.0`. No test.

16. **`_bracket_interp` / `_nearest`** in `atmosphere_grid.jl:179-196`. The bilinear lookup that drives every pixel of every render. No test.

## Regression hazards — changes that would silently pass tests

Each item below is a code change that **(a) breaks documented physics and (b) does not flip any assertion in `test/runtests.jl`**.

1. **Replace `kappa_ff` in the B=0 branch of `_compute_magnetic_opacities!` (`magnetic_atmosphere.jl:291`) with `0.5 * kappa_ff`.** Non-magnetic atmosphere flux halves. No test exercises B=0 path of the magnetic solver. (`solve_atmosphere` has no flux test either.)

2. **Replace the bottom boundary `B[j,j] = 1.0; Q .= Bν` in `_feautrier_single` (`magnetic_atmosphere.jl:404-407`) with `Q .= 0.5*Bν` (mistakenly applying the per-mode factor twice).** Emergent spectrum darkens by a fixed factor; the magnetic flux smoke test at `rtol=0.25` will not fail because the flux correction loop (`magnetic_atmosphere.jl:124-128`) silently rescales by a factor up to `0.9`–`1.1` per iteration, masking the bug across iterations.

3. **In `_rybicki_two_mode` (`magnetic_atmosphere.jl:486-491`), change `for j in 1:2` to `for j in 1:1`.** Temperature correction now uses only mode 1; T profile drifts. Magnetic flux test still passes (flux correction loop compensates); B=0 limit is unaffected; nothing else exercises the T profile.

4. **Drop the Suleimanov flux-correction term entirely (`magnetic_atmosphere.jl:124-128`).** Flux conservation degrades to ~10%. Magnetic flux test at `rtol=0.25` still passes.

5. **In `vacuum_polarization_parameter` (`dielectric_tensor.jl:224`), swap the sign of `D^2 / εp`.** The hard-coded `β ≈ 19.4117` test (`runtests.jl:52`) catches this *at one point only*. The test point happens to be where the term is large and positive; at other points (e.g. low B or low ω) the bug could be activated without the test noticing — but here it would fail, so this particular case is actually covered.

6. **Increase `coulomb_log_magnetic`'s `maxevals` cap from 2000 to 200 (typo)** (`coulomb_magnetic.jl:54`). QuadGK returns a less-converged value; the single Λ₀ ≈ 7.4148 test at `rtol=5e-4` may or may not catch this depending on the integrand's behaviour at the tested point — but Λ for α=±1, which are not tested, could be off by orders of magnitude.

7. **Change the `α_fine` constant in `src/constants.jl:44` from `7.2973525693e-3` to `7.297e-3`** (rounding). Vacuum coefficient regression-locked numbers will shift in the 4th–5th digit; this *would* fail the `rtol=1e-10` test at `runtests.jl:46-48`. Conversely, **adding a unit prefix scale to `B_Q`** (e.g. dividing by `4π` "to fix the convention") would fail the same test — so the fingerprint tests *do* catch constants tampering, even if at the cost of being annoying when you legitimately update constants.

8. **In `_compute_magnetic_opacities!` (`magnetic_atmosphere.jl:281`), replace `max(mode_absorption(...), 1e-30)` with `max(mode_absorption(...), 1e-6)`.** Opacity floor 24 orders of magnitude higher than intended; the τ ≥ 80 test still passes (more opacity → higher τ), the flux test passes (LTE still satisfied at high τ), but T profile and spectral shape are wrong.

9. **Swap `m_p` and `m_e` in `n_e = ρ / (m_p + m_e)`** at `magnetic_modes.jl:240` or `magnetic_ff.jl:113`. The shift is ~0.05% — likely too small for the magnetic flux smoke test, certainly too small for the τ ≥ 80 test. The vacuum-mode test at `runtests.jl:43` *does* feed `n_e = 1.0/(m_p + m_e)` so a sign/swap change in one place would not be caught if the other site is changed consistently.

10. **In `_solve_feautrier_mode!` (`magnetic_atmosphere.jl:343`), change `if τ_cum > 80.0 && τ_eff_cum > 10.0` to `if τ_cum > 80.0 || τ_eff_cum > 10.0`.** In scattering-dominated layers the LTE bottom BC is applied above the thermalisation depth. T profile and emergent flux silently degrade. The HANDOFF call-out about the "thermalisation depth guard" (`HANDOFF.md:83`) has no test backing.

11. **Set `flux_damping` default from 0.5 to 0.0** (`magnetic_atmosphere.jl:63`). Flux correction disabled in production runs; the test (`:97-117`) explicitly does not pass `flux_damping`, so it uses default — *but* the magnetic flux smoke test asserts only `rtol=0.25`. The test will probably still pass.

12. **In the bilinear lookup `atmosphere_grid.jl:117-134`, replace `1-fT` with `1+fT`.** Negative weights; spectra extrapolated wildly outside the (T, B) grid. No test of the render pipeline at all.

- `shell> python3 verification/check_suleimanov_fig2_metrics.py` and assert exit code 0; or

The `eos_checks.jl` "PASS"/"FAIL" pattern is actively dangerous: a fresh agent runs the script, sees five PASS lines among the output, and assumes everything is good — even if the M_max FAIL line scrolled past. **No mechanism enforces that "PASS" actually corresponds to a return code or test failure.** This is "manual verification existing, no automation".

`refs/code/McPHAC/OUT_T*/` directories exist but nothing in `verification/` or `test/` actually reads them. The "T profile matches McPHAC within 1.2%" claim is unbacked by any code in the tree.

## Numerical tolerance hygiene

| Site | Tolerance | Justified? |
|------|-----------|------------|
| `runtests.jl:20` `κ_total ≈ κ_abs + κ_scat rtol=1e-12` | Machine precision | Yes, but this is testing a definition (`mode_opacity = mode_absorption + mode_scattering`), not physics. |
| `runtests.jl:35` `Λ₀ ≈ 7.4148 rtol=5e-4` | 0.05% | Reasonable: `quadgk` is called with `rtol=1e-4`; matches integration accuracy. |
| `runtests.jl:46-48` `rtol=1e-10` (vacuum coefficients) | 1e-10 | **Excessive.** These are functions of `α_fine`, `B_Q`, `B` only; the math is exact arithmetic on hard-coded constants. The tight rtol makes the test fail on any *constant update*, not on any physics regression. Practical effect: discourages improving CODATA values. |
| `runtests.jl:52-65` `rtol=1e-8` to `1e-10` (mode parameters and weights) | 1e-8/1e-10 | **Too tight to be a physics check, too loose to be a bit-exact check.** Mostly catches changes to the inner solver, which is the change-detection role the suite is implicitly playing. |
| `runtests.jl:93` `minimum(τ[end, :, :]) >= 80.0` | Hard bound | Reasonable; matches `_build_initial_column` guarantee. |
| `runtests.jl:116` `flux / (σ_SB T_eff^4) ≈ 1.0 rtol=0.25` | **25%** | **Far too loose.** HANDOFF and the solver's own `flux_tol` default (`magnetic_atmosphere.jl:62`) are 1%. A 24% systematic drift would be invisible. |

The pattern is bimodal: either pin to last-digit precision (catches changes, not bugs) or accept 25% slack (catches nothing). There is no middle band where a tolerance was chosen with reference to actual physics-paper agreement.

## Test isolation and infrastructure

- **No `[extras]` / `[targets]` table** in `Project.toml`. `using Test` works because `Test` is a Julia stdlib, but `Pkg.test("NeutronStar")` would still work — barely. On CI this is fragile.
- **Filesystem dependency**: `load_gaunt_table("refs/code/McPHAC/gffgu.dat")` is invoked at `runtests.jl:74` and `:97`. The tests assume CWD is the project root. Running `julia --project=. test/runtests.jl` from a subdirectory fails with `SystemError`.
- **No CI workflow**. No `.github/workflows/`, no `.gitlab-ci.yml`, no `Makefile`. The HANDOFF reproduction commands are documented but not executed automatically. The reviewer was told "tests pass" — this is taken on faith; a freshly-cloned repo on CI has not been demonstrated.
- **No `Random.seed!`** is needed (no stochastic tests).
- **No precompile guard** (`Pkg.precompile()`, `__precompile__()`). First-test launch JIT-compiles ~6000 LOC; subsequent runs within the same Julia session reuse the cache. CI cold-start time is unmeasured.
- **No `@testset` for verification scripts**. The Suleimanov harness is a separate Python process. Running the Julia test suite gives no signal about Suleimanov agreement.

## Performance / runtime

None of the timing claims in HANDOFF.md is testable:

- > "256×256×50 render in ~1.3 s after the grid is built" — `HANDOFF.md:41`
- > "Build cost: ~14 s for B=0, ~12 min with B=10¹² (60-iteration magnetic case)" — `HANDOFF.md:155-157`
- > "Frequency-adaptive depth grid (2× faster)" — `README.md:37`

No `@benchmark`, no `@time`, no max-iteration assertion. A 10× regression in either grid-build or render time would surface only through user pain. (To be fair: `BenchmarkTools` would add a transitive dependency, and time-based tests are flaky on CI. A reasonable substitute is asserting iteration counts.)

The smoke test (`runtests.jl:97-117`) uses `max_iter=60`, `tol=5e-4` (looser than the HANDOFF-described `tol=1e-4`), reduced K=16 M=4 N=50. This is fine for fast CI but means the test does **not** exercise the production configuration claimed elsewhere.

## Suggested test additions — prioritised

These would, in roughly increasing order of effort, materially raise the regression-detection floor.

### Tier 1 — one-liners that catch the named-and-claimed regressions (do these first)

1. **TOV canonical 1.4 M_☉ check** — `@test solve_tov(<bisected ρ_c>, BSk21_params).R_km ≈ 12.6 atol=0.2`. Two lines including the bisection.

4. **`magnetic_colatitude` pole/equator** — pole points + obliquity=0 yield θ_B=0; equator + π/2 yields π/2. Three asserts.
5. **`surface_temperature(0) == T_pole`** and `surface_temperature(π/2) == T_eq`.
6. **`surface_Bfield(0) == B_pole`** and `surface_Bfield(π/2) == 0.5 * B_pole`.

### Tier 2 — high-value invariants

7. **B=0 consistency**. Run `solve_magnetic_atmosphere(1e6, 2e14, 0.0, 0.0, gaunt; ...)` and `solve_atmosphere(1e6, 2e14, gaunt; ...)` with matched K/M/N. 11. **`solve_tov(5e13, BSk21_params).compactness < 0.01`** (Newtonian limit).

### Tier 3 — physics-correctness over a parameter sweep

12. **θ_B at boundaries**. `mode_opacity(1, ν, 0.0, B, T, ρ)` and `mode_opacity(1, ν, π/2, B, T, ρ)` finite and positive; similarly for `polarization_weights_vacuum`.

15. **Frequency-grid edge intensities**. At ν = `ν_grid[1]` and ν = `ν_grid[end]`, emergent intensity is finite, non-negative, and (for the low end) bounded by Rayleigh-Jeans of the surface temperature.
16. **`build_atmosphere_grid` interpolation continuity**. Build a 3×1 (T_eff, B=0) grid; sample at intermediate T_eff; assert interpolated spectrum is between the bracketing models within 10% per channel.
